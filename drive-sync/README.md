# Garmin Health Sync — проверка записи в Google Drive

Этот каталог разворачивается как отдельный Vercel-проект с Root Directory `drive-sync`. Проверочный маршрут работает в Preview. Для него достаточно Google OAuth и отдельного ключа запуска. Garmin Connect, данные тренировок, расписание и учётные данные MCP в проверке не участвуют.

## Одноразовая авторизация

1. В проекте Google Cloud `garmin-health-sync-515510` включите Google Drive API и Google Picker API. Нужен OAuth-клиент **Web application** с точным redirect URI `http://127.0.0.1:53682/oauth/callback` и ключ Google Picker, ограниченный Google Picker API и локальным origin `http://127.0.0.1:53682/*`. Для Picker используйте числовой номер того же проекта.
2. Скопируйте `.env.example` в `.env.drive-local` внутри `drive-sync` и заполните переменные локально. Оба файла с рабочими значениями исключены из Git. Используйте приватную учётную запись ОС и не открывайте значения в записи экрана, чатах и логах.
3. Из `drive-sync` выполните `node --env-file=.env.drive-local scripts/authorize.mjs`. Откройте локальную ссылку из терминала, подтвердите запрос Google и выберите существующую папку **Garmin Health Sync**. Google Picker предоставляет приложению доступ к папке при ограниченном разрешении `drive.file`. Скрипт проверяет ID и возможность записи, заранее резервирует ID тестового файла и сохраняет параметры в `.env.drive-preview`.
4. Добавьте пять переменных из `.env.drive-preview` в параметры Preview отдельного Vercel-проекта. Для `GOOGLE_DRIVE_CLIENT_SECRET`, `GOOGLE_DRIVE_REFRESH_TOKEN` и `DRIVE_SMOKE_TOKEN` используйте Sensitive. Сохраните созданный ID файла для повторных запусков. Включите Automatic Exposure of System Environment Variables, чтобы функция могла проверить значение VERCEL_ENV. Пересоберите Preview с этими параметрами. Существующий MCP-проект и его переменные для этого не нужны.

OAuth-клиент с типом аудитории **External** и статусом **Testing** выдаёт для `drive.file` refresh token на семь дней. Этого достаточно для проверки. Перед настройкой регулярной выгрузки проверьте режим публикации проекта и срок действия учётных данных.

## Проверка

В `drive-sync` выполните `npm test` для проверки поведения с имитацией Google API. Для живой проверки вызовите `POST /api/drive-smoke` на URL нового Preview, передав `Authorization: Bearer <DRIVE_SMOKE_TOKEN>` через переменную окружения. Если Preview защищён Vercel, используйте авторизованный доступ и сохраняйте защиту Preview включённой.

Успешный ответ содержит `verified: true`, ID файла и ID папки. В Google Drive должен появиться один файл `garmin-drive-smoke.json` с синтетическим JSON. Функция сверяет папку и содержимое сразу после записи. При повторном вызове используется тот же ID, ответ содержит `created: false`. Ошибки содержат только имя этапа и, если доступен, HTTP-статус Google. После проверки сохраните секреты только в выбранном защищённом хранилище и уберите рабочие локальные копии.

## Ежедневная выгрузка

Рабочий каталог Vercel — `drive-sync`. Выгрузка включается только при совпадении
системного `VERCEL_PROJECT_ID` со значением `GARMIN_SYNC_PROJECT_ID` отдельного
проекта `fox-cce3/garmin-health-sync-preview`. В тестовом Preview вызовите
`POST /api/garmin-sync` с заголовком `Authorization: Bearer …` и включённой
защитой Preview. В Vercel Cron используется `GET` с тем же серверным
`CRON_SECRET`. Расписание `0 2 * * *` соответствует окну 09:00–09:59
Asia/Novosibirsk на Hobby. Vercel запускает Cron на Production-развёртывании
**этого отдельного проекта**. Развёртывание Preview само расписание не активирует.
Нужны системные переменные Vercel и Fluid Compute для `maxDuration: 120`.

Переменные для нужной среды отдельного проекта:

| Переменная | Назначение |
| --- | --- |
| `GARMIN_SYNC_PROJECT_ID` | ID отдельного Vercel-проекта |
| `GARMIN_API_KEY` | Garmin Personal API key владельца данных |
| `GOOGLE_DRIVE_CLIENT_ID` | ID OAuth-клиента Google Cloud |
| `GOOGLE_DRIVE_CLIENT_SECRET` | Секрет OAuth-клиента |
| `GOOGLE_DRIVE_REFRESH_TOKEN` | Refresh token OAuth с правом `drive.file` |
| `CRON_SECRET` | Случайный секрет длиной не менее 32 символов |
| `BLOB_READ_WRITE_TOKEN` | Ключ отдельного private Vercel Blob для блокировки и таблицы идентификаторов |

Храните секреты в типе Secret. Private Blob хранит только даты, служебную
блокировку и ID файлов Drive. Данные Garmin сохраняются в исходной папке
`Garmin Health Sync`. Не очищайте таблицу идентификаторов, пока существуют
соответствующие файлы Drive.

Обрабатываются три последние завершённые даты в Asia/Novosibirsk. Один файл
`garmin-daily-YYYY-MM-DD.json` на дату, `schemaVersion: 1`,
`source: garmin-connect`, раздел `metrics` содержит `hrv`, `spo2`, `sleep`,
`heartRate`, `steps`, `activity`, `workouts`. Ночные показатели относятся к
дате окончания ночи. Тренировки группируются по времени старта, переведённому
из UTC, уникальны по `activityId` и не включают отдельные части мультиспорта.
Суточный минимум SpO₂ — `spo2.lowestSpO2`. Ночной минимум — отдельное поле
`sleep.lowestSpO2Value`, если Garmin вернул его.

`ok` означает полученные данные, `no_data` — отсутствие измерения, `error` —
ошибку источника, `stale` — сохранённое последнее успешное значение и статус
последней попытки. Ноль шагов и пустой список тренировок допустимы.
Повтор с идентичными данными не изменяет файл. Неполный поиск и конфликт
имён останавливают запись для соответствующей даты. Ответ содержит только
даты, техстатусы и IDs файлов. Ошибка одного дня не блокирует другие.
Еженедельный читатель проверяет все семь запрошенных дат, включая отсутствующие
файлы и дубликаты. Сразу после включения ежедневной выгрузки история постепенно
накапливается.

Google access token обновляется на каждом запуске. Если Google сообщает
`oauth_reauthorization_required`, переполучите согласие и выберите ту же папку
через Picker, замените refresh token только в нужной среде и пересоберите её.
Для постоянной работы внешнего OAuth-приложения переведите экран согласия в
In production **в Google Cloud** и получите новый refresh token. Режим Google
OAuth независим от окружений Vercel. Старый токен используйте до проверки нового,
если это возможно, и удалите локальные рабочие копии после переноса секретов.
