# Garmin Health Sync — проверка записи в Google Drive

Этот каталог разворачивается как отдельный Vercel-проект с Root Directory `drive-sync`. Проверочный маршрут работает в Preview. Для него достаточно Google OAuth и отдельного ключа запуска. Garmin Connect, данные тренировок, расписание и учётные данные MCP в проверке не участвуют.

## Одноразовая авторизация

1. В проекте Google Cloud `garmin-health-sync-515510` включите Google Drive API и Google Picker API. Нужен OAuth-клиент **Web application** с точным redirect URI `http://127.0.0.1:53682/oauth/callback` и ключ Google Picker, ограниченный Google Picker API и локальным origin `http://127.0.0.1:53682/*`. Для Picker используйте числовой номер того же проекта.
2. Скопируйте `.env.example` в `.env.drive-local` внутри `drive-sync` и заполните переменные локально. Оба файла с рабочими значениями исключены из Git. Используйте приватную учётную запись ОС и не открывайте значения в записи экрана, чатах и логах.
3. Из `drive-sync` выполните `node --env-file=.env.drive-local scripts/authorize.mjs`. Откройте локальную ссылку из терминала, подтвердите запрос Google и выберите существующую папку **Garmin Health Sync**. Google Picker предоставляет приложению доступ к папке при ограниченном разрешении `drive.file`. Скрипт проверяет ID и возможность записи, заранее резервирует ID тестового файла и сохраняет параметры в `.env.drive-preview`.
4. Добавьте пять переменных из `.env.drive-preview` в параметры Preview отдельного Vercel-проекта. Для `GOOGLE_DRIVE_CLIENT_SECRET`, `GOOGLE_DRIVE_REFRESH_TOKEN` и `DRIVE_SMOKE_TOKEN` используйте Sensitive. Сохраните созданный ID файла для повторных запусков. Включите Automatic Exposure of System Environment Variables, чтобы функция могла проверить значение VERCEL_ENV. Пересоберите Preview с этими параметрами. Существующий MCP-проект и его переменные для этого не нужны.

OAuth-клиент с типом аудитории **External** и статусом **Testing** выдаёт для `drive.file` refresh token на семь дней. Этого достаточно для проверки. Перед настройкой регулярной выгрузки проверьте режим публикации проекта и срок действия учётных данных.

## Проверка

В `drive-sync` выполните `npm test` для проверки поведения с имитацией Google API. Для живой проверки вызовите `POST /api/drive-smoke` на URL нового Preview, передав `Authorization: Bearer <DRIVE_SMOKE_TOKEN>` через переменную окружения. Если Preview защищён Vercel, используйте авторизованный доступ и сохраняйте защиту Preview включённой.

Успешный ответ содержит `verified: true`, ID файла и ID папки. В Google Drive должен появиться один файл `garmin-drive-smoke.json` с синтетическим JSON. Функция сверяет папку и содержимое сразу после записи. При повторном вызове используется тот же ID, ответ содержит `created: false`. Ошибки содержат только имя этапа и, если доступен, HTTP-статус Google. После проверки сохраните секреты только в выбранном защищённом хранилище и уберите рабочие локальные копии.
